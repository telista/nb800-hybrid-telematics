1. PROBLEM TANIMI: MASABAŞI vs. SAHA ORTAMI ÇELİŞKİSİ
--------------------------------------------------------------------------------
Masabaşı geliştirme ortamında bilgisayarınız ile NB800 yönlendiricisi birbirine
doğrudan bir Ethernet kablosu ile bağlıdır:
  * Router IP       : 192.168.1.1
  * Bilgisayar IP   : 192.168.1.2
  * Alpine Konteyner: 192.168.1.10 (Bridged Mod + Statik IP)

BU YAPI MASABAŞINDA ÇOK PRATİKTİR ÇÜNKÜ:
  * Bilgisayarınızdan tek komutla (ping 192.168.1.10) konteynere erişebilirsiniz.
  * Router arayüzüne kolayca bağlanıp imaj yükleyebilirsiniz.

FAKAT CİHAZ BU AYARLARLA SAHAYA / ARACA GİTTİĞİNDE SİSTEM ÇÖKER ÇÜNKÜ:
  1. Cihaz başka bir LAN'a (örneğin araç içi switch, filo yönetim ağı, fabrika
     veya ofis ağı: 10.x.x.x ya da 172.16.x.x) takıldığında, Alpine hâlâ eski
     192.168.1.10 adresinde ısrar eder.
  2. Ağ geçidi (192.168.1.1) o ağda var olmayacağı için konteyner dış dünyaya
     paket gönderemez; internete ve uzak MQTT sunucusuna erişemez.
  3. Eğer NB800 sadece 4G/LTE (Hücresel SIM kart) ile sahaya çıkarsa ve Ethernet
     portuna hiçbir şey takılmazsa, Bridged arayüzü link alamayabilir veya
     konteyner hücresel internete çıkış kapısını bulamaz.


--------------------------------------------------------------------------------
2. ÇÖZÜM SEÇENEKLERİ
--------------------------------------------------------------------------------

SEÇENEK A: BRIDGED MOD + DİNAMİK IP (DHCP)
------------------------------------------
Konteynerin statik IP kullanması yerine ağdaki DHCP sunucusundan otomatik IP
alması sağlanır.

* Nasıl Yapılır?
  Alpine içindeki /etc/network/interfaces dosyası şu şekilde düzenlenir:
    auto lo
    iface lo inet loopback

    auto eth0
    iface eth0 inet dhcp

* Artıları:
  - Cihaz hangi LAN'a takılırsa takılsın o ağa uygun bir IP alır ve o ağ üzerinden
    internete çıkabilir.
* Eksileri / Riskleri:
  - Konteynerin IP'si her açılışta veya ağ değişiminde farklılaşır (IP takibi zorlaşır).
  - Ethernet kablosu takılı değilken veya ağda bir DHCP sunucusu yoksa konteyner
    IP alamaz, beklemeye girer (timeout gecikmeleri yaşanır).
  - Yönlendiricinin kendi iç MQTT broker'ına bağlanırken router'ın o anki dinamik
    IP'sini bilmesi gerekir.


SEÇENEK B: ROUTED MOD (ENDÜSTRİYEL STANDART & ÖNERİLEN SAHA MODELİ)
------------------------------------------------------------------
Endüstriyel ağ geçitlerinde ve araç telemetrisinde (ITxPT standartları dahil)
kabul gören en kararlı yöntem "Routed (Yönlendirmeli) Mod"dur.

* Çalışma Mantığı:
  Konteyner, router'ın dışındaki fiziksel Ethernet soketine DEĞİL; router'ın
  kendi işletim sistemi (NRSW) ile konteyner arasında açılan "Özel Sanal Ağ"a
  bağlanır. Bu ağ fiziksel dünyadan tamamen izoledir:
    - Sanal Ağ Bloğu   : 192.168.100.0/24
    - Router İç Sanal IP: 192.168.100.1 (Gateway & Host)
    - Konteyner Sabit IP: 192.168.100.2 (Alpine Guest)

* SAHADA SAĞLADIĞI BÜYÜK AVANTAJLAR:
  1. DIŞ DÜNYADAN %100 BAĞIMSIZLIK:
     NB800'ün dış Ethernet portu ister 10.0.0.x alsın, ister 172.16.x.x alsın,
     isterse Ethernet kablosu tamamen sökülüp sadece 4G hücresel modemle çalışsın;
     Alpine konteyneri ile Router arasındaki haberleşme daima 192.168.100.1 <->
     192.168.100.2 olarak sabit kalır!
  2. DAHİLİ MQTT BROKER KARARLILIĞI:
     Alpine içindeki Python ajanı, router üzerindeki dahili Mosquitto broker'a
     daima "192.168.100.1:1883" adresinden bağlanır. Asla IP aramak veya DNS
     çözmek zorunda kalmaz.
  3. DIŞ İNTERNETE ÇIKIŞ (NAT / MASQUERADE):
     Konteyner uzak bulut sunucusuna (MQTTS 8883) bağlanmak istediğinde, paketler
     router'ın çekirdeğine (192.168.100.1) gelir. NB800 o an internet neredeyse
     (Ethernet WAN veya 4G WWAN) o hat üzerinden otomatik IP Maskelemesi (NAT)
     yaparak paketi dışarı iletir. Hat kopsa veya 4G'ye geçse bile konteynerin iç
     ağ yapılandırmasına dokunulmaz.
  4. SİBER GÜVENLİK VE İZOLASYON:
     Konteyner yerel ağdaki virüs, port tarama ve yetkisiz erişimlerden tamamen
     korunur. Dış ağdan konteynere yalnızca router güvenlik duvarından izin
     verilen portlar ulaşabilir.


--------------------------------------------------------------------------------
3. ROUTED MODA GEÇİŞ İÇİN YAPILACAK AYARLAR
--------------------------------------------------------------------------------

1. Alpine Tarafı (/etc/network/interfaces):
------------------------------------------
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet static
    address 192.168.100.2
    netmask 255.255.255.0
    gateway 192.168.100.1

2. Alpine DNS (/etc/resolv.conf):
---------------------------------
nameserver 192.168.100.1
nameserver 8.8.8.8

3. NB800 Web Arayüzü (Virtual Guests -> Guest Networking):
----------------------------------------------------------
* Mode            : Routed
* Guest Interface : eth0
* Address         : 192.168.100.2
* Netmask         : 255.255.255.0
* Gateway         : 192.168.100.1


--------------------------------------------------------------------------------
4. SAHAYA ÇIKMADAN ÖNCE KRİTİK KONTROL LİSTESİ (CHECKLIST)
--------------------------------------------------------------------------------

[ ] 1. Ağ Modu:
    Konteynerin "Routed Mod"a alındığını ve 192.168.100.1 gateway'ini gördüğünü
    doğrulayın.

[ ] 2. Dahili MQTT Broker İletişimi:
    Arena betiği (host katmanı) ve Python ajanı (LXC katmanı) arasındaki yerel
    konuların (telemetri, gnss, system, cmd) 192.168.100.1:1883 üzerinden aktığını
    test edin.

[ ] 3. SQLite WAL ve Güç Kesintisi Koruması:
    Araç kontağı aniden kapandığında SQLite veritabanının bozulmaması için
    kodunuzda şu PRAGMA ayarlarının yapıldığından emin olun:
      - PRAGMA journal_mode = WAL;
      - PRAGMA synchronous = NORMAL;
      - PRAGMA temp_store = MEMORY;
      - PRAGMA wal_autocheckpoint = 1000;

[ ] 4. Disk Dolma Koruması (Store-and-Forward Kotası):
    Araç günlerce hücresel kapsama alanı dışında kalırsa diskin dolup sistemi
    kilitlememesi için SQLite tablonuzda FIFO (First-In, First-Out) veya azami
    satır/dosya boyutu sınırı (örn. azami 100 MB kota) bulunduğunu teyit edin.

[ ] 5. Zaman Senkronizasyonu (RTC / GNSS):
    NB800'ün GNSS modülünden zaman senkronizasyonu açık olmalı
    (System -> Time -> Sync time from GNSS: Enabled). İnternet olmadığında dahi
    telemetri zaman damgalarının doğruluğu buna bağlıdır.

[ ] 6. Supervisor Otomatik Yeniden Başlatma:
    Python ajanı herhangi bir beklenmeyen istisna ile çökerse, supervisord'nin
    ajanı anında yeniden kaldırdığını (autorestart=true) doğrulayın.
